## Probe limits (not catalog defects)

- **Rule scope by self-report under-counts.** A model often names only some attached rules (Claude
  K3 1/8, K4 3/7). A named rule is hard evidence; an omitted one is not. No rule was ever named
  outside its globs.
- **Copilot P6 (read one file, then list the rules) cannot pass by design.** Copilot loads
  instructions lazily, when it works on a file, not when it answers a question. The
  review and edit transcripts are the evidence instead (table above).
- The first full run's K5–K7 Claude rows were a 429 weekly limit, not results. The harness now marks
  API errors as `ERROR` and stops the run; those probes were re-run.

**F3:** sigil now writes `.mcp.json` correctly (unit-tested), and `copilot mcp list` confirms the
CLI looks there ("Workspace: .mcp.json or .github/mcp.json"). Workspace servers load only once the
folder is trusted, which Copilot asks about on the first interactive launch in a folder; `copilot -p`
never asks ([CLI reference, MCP server loading priority](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-command-reference#mcp-server-loading-priority)).
Re-run K2 P10 after trusting `C:\WorkspaceMaku\TestCaI` once.

**F5:** for "review … for bugs and security problems", Copilot routes to its built-in
`security-review` agent even with the language now named. Python, Angular and CLI prompts picked the
catalog agent. This is recorded as a provider preference, not a catalog defect; naming the agent
("use ts-security-auditor") works on both providers.
