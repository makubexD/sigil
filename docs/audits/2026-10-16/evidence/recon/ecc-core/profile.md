## Purpose and users
**Fact**: "a Claude Code plugin - a collection of production-ready agents, skills, hooks, commands, rules, and MCP configurations" (CLAUDE.md:7). AGENTS.md:3 counts 71 agents, 311 skills, 97 commands. Users are individual Claude Code developers first; Codex, Cursor, Copilot, OpenCode, Kiro, Gemini, Zed and others get "capability-limited adapters" (README.md:142). It is a very broad harness (marketing, healthcare, network, ML, supply-chain agents), of which code-quality material is one slice.

## Architectural model
- **Authoring**: hand-written Markdown with YAML frontmatter (agents: `name, description, tools, model`; rules: optional `paths:`). No generation or templating: the 71 agents each repeat a Prompt Defense Baseline (~994 B, 71 of 71 files, counted by script) and a near-identical review skeleton. Per-harness copies (`.cursor/rules/*.md` with `globs`/`alwaysApply:false`, `.kiro/steering` with `inclusion: always`, `.opencode/commands`, `.github/copilot-instructions.md`) are separate files.
- **Composition**: rules layer as `common/` plus `<language>/` files that open with "This file extends common/x.md" (108 of 121 rule files). Precedence is prose only: "language-specific rules take precedence" (rules/README.md:130); no tool enforces it.
- **Distribution**: npm package `ecc-universal`, plugin marketplace, `install.sh/.ps1`. Manifest-driven selective install: 46 modules, 7 profiles, components `lang:/framework:/capability:`, `--with/--without`, `ecc-install.json` (schemas/ecc-install-config.schema.json), per-target adapters (13+), install-state with ownership guard so user-authored files are not overwritten (scripts/lib/install/ownership-guard.js:27) and doctor/repair.
- **Activation**: rules with `paths:` load on matching files; `common/` has no frontmatter so it is always on (10 files, 19,408 B); agents by description; commands explicit; hooks by Claude Code events through a 3-layer dispatcher (`hooks.json` -> `plugin-hook-bootstrap` -> `run-with-flags` -> script).
- **Surface policy**: AGENTS.md says `skills/` is canonical and `commands/` is a "legacy slash-entry compatibility surface" (Workflow Surface Policy), yet 97 commands remain (402,897 B).

## Hooks in depth (fact unless marked)
- **Fail mode**: safety hooks fail closed. `pre-bash-dispatcher` exits 2 on truncated stdin and on crash (scripts/hooks/pre-bash-dispatcher.js:29,41); `config-protection` refuses truncated payloads (config-protection.js:149-155); `run-with-flags` has a closed-set for gateguard Edit/Write and MCP health (run-with-flags.js:20-24). Quality/telemetry hooks fail open (`stop-format-typecheck` suppresses pass-through and exits 0, stop-format-typecheck.js:262-268).
- **Block vs warn**: Blocks (exit 2): `block-no-verify`, `config-protection`, `commit-quality` (strict only; `debugger` and secret patterns are `error`, console.log `warning`, TODO `info`, pre-bash-commit-quality.js:107-128,502), `dev-server-block`, GateGuard denials. Warn only: console.log (edit and Stop), doc-file warning ("Exit code 0 always", doc-file-warning.js:11), design-quality, quality-gate (silent unless `ECC_QUALITY_GATE_STRICT=true`, quality-gate.js:71), git-push reminder, suggest-compact, context monitor.
- **Format/typecheck at Stop**: PostToolUse accumulator writes edited JS/TS paths to `os.tmpdir()/ecc-edited-<session>.txt`; at Stop one formatter run per project root (biome/prettier `--write`) and one `npx tsc --noEmit --pretty false` per tsconfig dir; budget `270_000` ms split evenly over batches (stop-format-typecheck.js:28-46); diagnostics filtered to edited files, first 10 lines each, written to stderr (:176-181). Formatter failures are swallowed (:114-116). **Inference**: because it exits 0 and writes to stderr, type errors reach the user at best, not necessarily the model, so it cannot make the agent fix them.
- **Documentation drift (fact)**: hooks/README.md:67-68 lists Prettier and `tsc` as PostToolUse-on-Edit hooks, but `post-edit-format.js`/`post-edit-typecheck.js` are not in `posttooluse-dispatcher.js` SYNC_HOOKS or hooks.json; only the accumulator is. Language `hooks.md` rules (22 files, 27,662 B) advise hooks (dotnet format, ng lint) with no implementation.
- **Profiles**: `ECC_HOOK_PROFILE`, `ECC_DISABLED_HOOKS`, `ECC_HOOKS_ENABLED`, plugin options, and `ecc/setup.json`, resolved in that order (scripts/lib/hook-flags.js:3-11). Runtime cost: each hook is a Node process; config-protection's comment cites "~50-100ms spawnSync overhead" avoided by in-process `run()`.
- **Severity table (BLOCK/WARN)**: rules/common/code-review.md:53-58 gives CRITICAL=BLOCK, HIGH=WARN, MEDIUM=INFO, LOW=NOTE, approval criteria at :113-115. Agents disagree: code-reviewer warns on HIGH (agents/code-reviewer.md:293), typescript-reviewer, csharp-reviewer and python-reviewer block on HIGH (typescript-reviewer.md:116, csharp-reviewer.md:94), `/code-review` blocks on HIGH (commands/code-review.md:71). This is an internal inconsistency.

## How ECC tests itself
- **Structure and consistency (strong)**: validators for agents (model in {haiku,sonnet,opus}, tools present), commands (references to agents/skills), hooks schema, install manifests, no personal paths, unicode safety, workflow security, catalog counts; 420 unit/integration test files; packed-artifact lifecycle test; matrix CI.
- **Rule content**: `validate-rules.js` only checks "Empty rule file" (scripts/ci/validate-rules.js). 
- **Prompt text pinning**: `tests/ci/code-reviewer-false-positive-guard.test.js:10-33` asserts required headings and phrases exist in the reviewer prompt. This protects against deletion, not against ineffective wording.
- **Behavioural evals (rare, one hook deep)**: GateGuard scenario replay (20 scenarios, 184 steps, labelled mustDeny/redundant; 0 bypasses, 0 redundant denials vs 38 for main, docs/gateguard/evaluation.md:81-83) and a real-agent A/B with placebo and minus-target arms, preregistered. Results: pilot "returned no information at all" (question-effectiveness.md:162); gate costs ~45% more turns and 28% more tokens with no outcome change (:180); confirmatory run not confirmed, p=0.210 (:445-454); cost "the most reliable number" (:470). `docker/context-profiles` has a 30-task repair corpus and 3-4 complex tasks with hidden graders and reference solutions for Full vs Lean skill sets; I did not locate the result tables in scope. No behavioural eval exists for rules or reviewer agents.

## Customization and precedence
Mechanisms: install profiles/modules/components; `--without`; rule namespace `~/.claude/rules/ecc/` to avoid collisions (rules/README.md:46-62); hook env profiles and per-id disabling; Hookify local rules in `.claude/hookify.*.local.md` (tracked-by-git rules disabled by default, hooks/README.md:179-183); `ecc-install.json`. Precedence: language over common (prose, rules/README.md:130), env > plugin option > managed config for hooks. There is no overlay/narrowing mechanism for rules or agents comparable to a per-project overlay file; consumers edit copies. Install state tracks ownership so updates do not overwrite user edits (#2964, ownership-guard.js:27).

## Strengths
- Reviewer discipline (code-reviewer gate and zero-findings clause) and evidence-based honesty (null results published).
- Config-protection, block-no-verify, fail-closed safety hooks, and profile/consent controls over automation.
- Strong Angular/React rules; path scoping keeps most rules off-context until needed.
- Install ownership/state, schema-validated manifests, broad CI.

## Weaknesses
- Scale: 4,615 tracked files; 71 agents/97 commands/311 skills; many domains unrelated to code quality. Maintenance burden is high and copies drift (README vs hooks; severity scales; counts).
- Mandatory dogma without evidence: 80% coverage, TDD for everything, 50-line functions.
- Most "quality" hooks are warn-only and JS-centric; no C#/Angular/Python automation behind the rules.
- No Angular reviewer; Python rules are stubs.
- Security via blocklist-style Prompt Defense copied 71 times.

## Top ideas worth taking
1. **Reviewer anti-noise protocol**: pre-report gate (cite line, name failure mode, read context, defend severity), proof for HIGH/CRITICAL, named false-positive classes, zero findings allowed. agents/code-reviewer.md:39-111,292-297. Raises precision, cuts review tokens. Evidence: phrase-pinning test only (tests/ci/code-reviewer-false-positive-guard.test.js:10), no behavioural eval.
2. **Config-protection hook**: block edits to lint/format configs and ignore files so the agent fixes code rather than lowering the bar; exempt build/test configs. scripts/hooks/config-protection.js:88-125, 203. Evidence: 20 KB unit test; no outcome eval.
3. **Fail-closed safety hooks, fail-open telemetry**: truncated input blocks only safety checks. pre-bash-dispatcher.js:27-29; run-with-flags.js:20-24. Evidence: tests/hooks/config-protection.test.js, hooks.test.js.
4. **Pre-registered, placebo-controlled hook evaluation with honest nulls**, including reference/naive overlays proving graders can fail. docs/gateguard/question-effectiveness.md:16-24,430. Evidence: the document itself (cost +37-45%, effect unproven) is the strongest argument for measuring any new automation before shipping.
5. **Adversarial verify-then-report pipeline**: parallel dimension reviewers, dedupe by evidence, verifier that defaults to refuted for unique CRITICAL/HIGH, fail closed on failed dimension. workflows/README.md:14-18. Evidence: none beyond design doc.
6. **Batch format/typecheck once at Stop**, scoped to edited files and tsconfig dirs, with an even time budget. stop-format-typecheck.js:3-14,28-46. Evidence: unit tests (tests/hooks); weakness is fail-open output.
7. **Run the toolchain before reviewing** (typecheck, eslint, CI status) and stop when red. agents/typescript-reviewer.md:19-22. Saves review tokens on code that fails mechanically.
8. **Hook profiles + per-id disable + consent disclosure** of automation capability groups. scripts/lib/hook-flags.js:3-11; scripts/lib/install/hook-consent.js:12-37.
9. **Hookify trust model**: project-local rules ignored when git-tracked unless explicitly trusted. hooks/README.md:179-183.
10. **Plan grounded in repo conventions with "do not invent a pattern"**, then explicit confirmation gate. commands/plan.md:17,63.
11. **Delegation completion contract** against orphaned child agents with observed failure as rationale. rules/common/agents.md:51-59.
12. **Install ownership state** so updates never overwrite user-edited files. scripts/lib/install/ownership-guard.js:27.
13. **Lean profile with a blocking token budget** for eager content, rest routed. manifests/context-profiles/lean@1.json:11; docker/context-profiles/README.md. Evidence: structural probes only; savings not certified (README says so).
14. **Path-scoped rules with version-awareness sections** (Angular) so advice adapts to project era. rules/angular/coding-style.md:16.
15. **Small single-lens reviewers** (silent failures, type invariants, comment rot) at ~2 KB each as fan-out members. agents/silent-failure-hunter.md, type-design-analyzer.md. Evidence: none.

Cautions to avoid copying: unmeasured mandatory TDD/80% rules, 71 copies of one defence block, HIGH-severity inconsistency, README-hook drift, and GateGuard-style gates without a cost budget.
