# Generated artifact index

## Objective

Give someone browsing the repo on GitHub one page that lists every installable artifact: its id, kind, description,
the packs that hold it, the targets that get it, and the `sigil add` command that installs it. The page is generated by
`npm run build` and committed, and a test fails when it is stale, the same pattern as `catalog/README.md`. Decided in
[ui-beyond-terminal-2026-11.md](../decisions/ui-beyond-terminal-2026-11.md), which also records the spike.

## Evidence

- The pattern to copy: `src/emit-catalog-readme.ts` writes `catalog/README.md` at the end of `npm run build`
  (`package.json` `build` script), and `test/catalog-readme.test.ts` compares the committed page with
  `renderCatalogReadme`. `docs/reference/capabilities.md` follows it too (`src/targets/emit-capability-doc.ts`).
- The per-artifact fields exist on `RegistryEntry` (`src/registry.ts:30-42`): `id`, `kind`, `title`, `description`,
  `tags`, `platforms` (all six targets), `relatedArtifacts`, `uses`. `buildRegistry` derives them from the resolved
  catalog.
- Pack membership is not in the registry. `getPackArtifacts` (`src/targets/shared/plugin-packs.ts:26`) expands both
  pack forms (`artifacts:` lists and `languages:` packs, 5 of the 14 today), but it drops `pluginExclude`, which is a
  plugin-only rule: `sigil add` still installs an excluded artifact. The spike reading only `artifacts:` lists left 140
  artifacts with no pack.
- `sigil add <kind>:<id> --target <t> --yes` is the install form; the spike installed
  `sigil add skill:shared/feature --target cursor --yes` with it.
- Spike size: 164 artifacts (templates excluded) gave 202 lines and 50 KB as one page, generated in about 12 ms.

## Out of scope

- A website, a server or a VS Code extension (the decision rules them out).
- Search and filtering beyond what a Markdown page gives.
- Artifact bodies on the page; the id links to the source file instead.

## Success criteria

- `docs/reference/artifacts.md` (or a split by kind if one page is too long) is generated by `npm run build`, linked from
  `catalog/README.md`, `README.md` and `docs/index.md` (row S8), and lists every non-template artifact.
- Pack membership comes from the same expansion `sigil add` uses for a pack, so the page and an install agree.
- Each row's id links to the artifact's source file, and its command is one a user can paste.
- A test fails when the committed page is stale; another checks that a `languages:` pack's members are listed.
- `npm run ci:local` green.

## Riskiest assumption

That people browse the repo on GitHub to choose artifacts. If they find sigil through a plugin browser instead, this
page goes unread, but it costs little to keep.

## Open questions

- One page or one per kind? The spike's one page is 50 KB; GitHub renders it, but a table that wide scrolls.
- Does a fork's own catalog get its own index (a `sigil index --markdown` flag), or only sigil's catalog?
- Which targets column: the registry's `platforms`, or the targets `add` would actually install to after skip rules
  (tool restriction, unrenderable hooks)? The second is truer and costs a render per target.
