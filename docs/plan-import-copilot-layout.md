# Plan: import from a Copilot `.github/` layout

Source: `docs/ideas/import-copilot-layout.md`. Branch: `feat/import-copilot-layout`.

`sigil import <dir> --from copilot` reads `.github/instructions/`, `.github/agents/`, `.github/skills/` and
`.github/prompts/` and writes catalog source. Targets do not change. A file that can't be imported safely is reported,

## What the code showed (run against the current build)

The brief's riskiest assumption, ids from filenames, is manageable. These are the bigger risks.

1. **Tools can silently widen.** The tolerant parser (`parse-markdown.ts`) leaves `tools: ["read", "search"]` as a string,
   which `splitToolsString` turns into `["read"`, `"search"]`. A YAML list stays an array, which `splitToolsString` turns
   into `[]`, and the translator emits no `tools`, which means **all tools**. `sigil add --target copilot` writes the
   JSON-array form, so every round-tripped agent hits the first case. The list case also affects Claude sources today.
2. **`parseFrontmatter` runs code.** `src/frontmatter-parse.ts` wraps gray-matter 4.0.3, which evals a `---js` block
   (confirmed: the body of the block executed). `.github/` files are untrusted, so import must never pass a raw source
   file to it. Step 2 parses with `js-yaml` under `JSON_SCHEMA` instead. See Out of scope for the existing callers.
3. **Tolerant parsing corrupts valid YAML.** `description: "He said \"hi\""` keeps its backslashes, and
   `description: >-` becomes the literal `>-`. sigil's own `yamlScalar` output is double-quoted, so this reaches round trips.
4. **`applyTo` globs can contain commas.** `spec/rule.ts:22` joins with `,`, so `**/*.{ts,tsx}` needs a brace-aware split.
5. **`allowed-tools` is space-separated** on Copilot (`shared/skill-sections.ts`). `splitToolsString` splits on commas only.
6. **Emitters add text that must come back out:** rule and agent `# <title>`, the rule's `<!-- Generated by sigil — … -->`,
   the skill's leading `## When to Use` and `**Arguments:**`, `${input:name}` in prompts, and lexicon values in every body
   and reference file. Leaving a `# title` in the body would print it twice on the next render.
7. **Rule and prompt filenames embed the namespace** (`typescript-ts-async.instructions.md`, `shared-explain-diff.prompt.md`).
   Without stripping it, a re-render writes `typescript-typescript-ts-async…`.
8. **Today's failure on `.github` is a crash.** `sigil import .github --language typescript` stops with
   `Invalid id 'typescript/ts-code-reviewer.agent'` and imports nothing, so any non-kebab stem would too.
9. **`prompt` isn't an import kind yet.** It is missing from `DiscoveredFile`, `CatalogFrontmatter` and `translateFrontmatter`.

## Decisions on the brief's open questions

- **Layout: explicit `--from claude|copilot`, default `claude`.** Existing commands behave exactly as before and nothing is
  guessed when a repo has both layouts. When nothing is found and the source has a `.github/` folder, the output suggests
  the flag.
- **`copilot-instructions.md` and `AGENTS.md`: reported, not imported.** Splitting on headings guesses at rule boundaries
  and scopes. Each is listed as unrecognised with a specific reason, so a team sees what still needs manual work.
- **`.claude/` directly: no change needed.** `sigil import .claude --language typescript --dry-run` already found both
  artifacts from a real `add --target claude`. Step 11 documents it.

## Known limits (documented in step 11, not fixed)

- `workflow` also renders to `.prompt.md`, so it comes back as `prompt`.
- `extends`, templates and `uses.rules` are flattened at render time. A `## Coding guidelines to apply` or `## Boundary`
  section stays in the body with a coverage note. `uses` is wired afterwards with `sigil patch`; `relatedArtifacts` has no
  `patch` flag, so it is set in the catalog file.
- Copilot `tools` values are copied as written; other targets may not know those names.
- A prompt's `tools` and `agent` are always listed as dropped, because the Copilot prompt spec emits fixed values
  (`agent: agent`, `tools: codebase, github`). A hand-narrowed prompt therefore gets wider on re-render, and the coverage
  report is where that shows.
- Only `*.instructions.md` directly in `instructions/` is read; subfolders are reported as unrecognised.
- `.chatmode.md` is not recognised.
- The trust scan blocks a file on any layout when `config/dangerous-command` matches its prose, such as a reviewer checklist
  naming `eval`. It hits 5 of the 36 catalog agents. Narrowing that rule is a separate security change.

## Out of scope

Cursor, Codex and other layouts; hooks and settings; round-trip fidelity beyond the fields the Copilot specs map; splitting
single-file instructions. **Hardening `parseFrontmatter` itself is a separate fix:** `src/load.ts:153` passes catalog files
to it, so a `--catalog-dir` pointing at someone else's catalog can run code. This feature does not depend on that fix.

## Steps

Every step keeps the eslint limits: 200 code lines per file, 20 per function, complexity 10, at most 4 params. Every step
adds its tests first and runs `npm run lint && npm test`. Tests import from `dist-cli`. Worker runs use **medium** at

### 1. Read tools lists in every written form `[worker:medium]`

Files: `src/authoring/import/translate-helpers.ts`, `test/authoring/import.test.ts`.

`splitToolsString(raw)`: an array returns its string items, trimmed, without empties. A string wrapped in `[` and `]` has
the brackets removed, then is split on commas with one layer of matching quotes stripped from each item. Any other string
keeps today's comma split. Non-string, non-array still returns `[]`.

| Input                  | Expected            |
| ---------------------- | ------------------- |
| `'Read, Grep'`         | `['Read','Grep']`   |
| `['Read','Grep']`      | `['Read','Grep']`   |
| `['Read',' ','Grep ']` | `['Read','Grep']`   |
| `'["read", "search"]'` | `['read','search']` |
| `"['read', 'search']"` | `['read','search']` |
| `'[read, search]'`     | `['read','search']` |
| `'[]'`                 | `[]`                |
| `undefined`, `3`       | `[]`                |

Also: `translateFrontmatter('agent', 'cs-x', { tools: ['Read','Grep'] }, opts)` has `tools: ['Read','Grep']`.

### 2. Parse untrusted frontmatter as YAML without gray-matter `[worker:medium]`

Files: `src/frontmatter-parse.ts`, `src/authoring/import/parse-markdown.ts`, `test/frontmatter-parse.test.ts`,
`test/authoring/parse-markdown.test.ts`.

- Add `parseYamlFrontmatter(text: string): Record<string, unknown> | undefined` to `frontmatter-parse.ts`, with a header
  comment saying it is the one for untrusted source files because gray-matter evals `---js`. It uses
  `yaml.load(text, { schema: yaml.JSON_SCHEMA })`. It returns `undefined` when loading throws or the result isn't a plain
  mapping, and it omits `FORBIDDEN_KEYS` (`src/config-merge/primitives.ts`).
- `parseMarkdown(filePath, opts?: { yamlFirst?: boolean })`: with `yamlFirst`, use `parseYamlFrontmatter(frontmatterText)`
  and fall back to `parseFrontmatterLines` when it returns `undefined`. Without it, nothing changes.

| Case (`yamlFirst: true` unless noted)                             | Expected                                 |
| ----------------------------------------------------------------- | ---------------------------------------- |
| `description: "He said \"hi\": ok"`                               | `He said "hi": ok`                       |
| `description: >-` with two indented lines                         | the folded text                          |
| `tools: ["read", "search"]`                                       | array `['read','search']`                |
| `description: Fix: the bug` (invalid YAML)                        | falls back; `Fix: the bug`               |
| a key `__proto__: x`                                              | absent; `Object.prototype` unchanged     |
| file starting `---js`, block sets `globalThis.SIGIL_PWNED = true` | not executed; the global stays undefined |
| frontmatter that is a YAML list                                   | falls back to the tolerant parse         |
| no opts, same `description: "He said \"hi\": ok"`                 | today's value, backslashes kept          |

### 3. Inverses of the lexicon and of Copilot placeholders `[worker:medium]`

Files: `src/targets/lexicon.ts`, `src/targets/prompt-args.ts`, `test/targets/prompt-args.test.ts`, new `test/targets/lexicon.test.ts`.

- `reverseLexicon(body, lexicon)` replaces each entry's literal `value` with `{sigil:<term>}`, longest value first. Where
  two terms share a value, the first in `LEXICON_TERMS` order wins.
- `fromCopilotPlaceholders(body)` returns `{ body, args }`. It turns `${input:name}` and `${input:name:hint}` into
  `{{name}}`. `args` lists each name once in first-seen order as `{ name }`, plus `description: hint` when a hint exists.
  The name pattern is `[\w-]+`. Other VS Code variables such as `${file}` stay as written.

| Case                                                                      | Expected                                                |
| ------------------------------------------------------------------------- | ------------------------------------------------------- |
| Copilot lexicon, `Read AGENTS.md`                                         | `Read {sigil:conventions-file}`                         |
| `see .github/skills/x`                                                    | `see {sigil:skills-dir}x`                               |
| `Target: the request you were given`                                      | `Target: {sigil:arguments}`                             |
| `applyLexicon(reverseLexicon(b, L), L)` for the bodies above              | equals `b`                                              |
| `${input:a} ${input:a}`                                                   | `{{a}} {{a}}`, `args: [{name:'a'}]`                     |
| `${input:a:Pick one: x}`                                                  | `{{a}}`, `args: [{name:'a',description:'Pick one: x'}]` |
| `${file}`                                                                 | unchanged, `args: []`                                   |
| `toCopilotPlaceholders(fromCopilotPlaceholders(b).body)` for `${input:a}` | `${input:a}`                                            |

### 4. Copilot frontmatter normaliser `[worker:medium]`

Files: new `src/authoring/import/copilot-fields.ts`, new `test/authoring/import-copilot-fields.test.ts`.

Pure module. It converts Copilot frontmatter into the shape the existing translators read, so `translate-kinds.ts` stays
unchanged. All notes use the exact wording below.

- `copilotSlug(stem, namespace?)`: lowercases, turns each run of characters outside `[a-z0-9]` into `-`, trims `-`, then
  strips a leading `<namespace>-`. Returns `''` when nothing remains.
- `splitGlobList(raw: string)`: splits on commas outside `{}`, trims, drops empties.
- `normalizeRuleFields(fm)`, `normalizeAgentFields(fm, slug)`, `normalizeSkillFields(fm, slug)` each return
  `{ frontmatter, notes: string[], refused?: string }`.
  - All: a string `description` has whitespace runs collapsed to one space and is trimmed.
  - Rule: `applyTo` (string or list) becomes `paths` and the key is removed. When absent: note
    `no applyTo in source; imported as **/*, which applies to every file`.
  - Agent: `name` is always set to `slug`. A different source name adds the note
    `name '<x>' not kept; the catalog name is '<slug>' (from the file name)`.
  - Agent `tools`, read with `splitToolsString`: key absent is unchanged. Key present with an empty result sets
    `refused: 'tools is empty, and an absent list would grant every tool'`. Exactly `['*']` removes the key and adds the note
    `tools ['*'] removed: an absent list already means all tools`. Otherwise `tools` becomes the array.
  - Skill: `name` equal to `slug` is removed; a different one adds the same `name` note and is removed. A string
    `allowed-tools` is split on `/[\s,]+/` into an array.

| Case                                                | Expected                                      |
| --------------------------------------------------- | --------------------------------------------- |
| `copilotSlug('typescript-ts-async','typescript')`   | `ts-async`                                    |
| `copilotSlug('shared-explain-diff','shared')`       | `explain-diff`                                |
| `copilotSlug('React_Guidelines')`                   | `react-guidelines`                            |
| `copilotSlug('___')`                                | `''`                                          |
| `splitGlobList('**/*.{ts,tsx},src/**')`             | `['**/*.{ts,tsx}','src/**']`                  |
| `splitGlobList('a , b,')`                           | `['a','b']`                                   |
| rule `applyTo: '**/*.ts,**/*.tsx'`                  | `paths` of both globs, no `applyTo`, no notes |
| rule, no `applyTo`                                  | no `paths`, the note                          |
| agent `name: 'Code Reviewer'`, slug `code-reviewer` | `name: 'code-reviewer'`, the note             |
| agent `tools: []`, `tools: ''`, `tools: null`       | `refused` set in all three                    |
| agent `tools: ['*']`                                | no `tools`, the note, not refused             |
| agent no `tools` key                                | no `tools`, no note, not refused              |
| skill `allowed-tools: 'Read Write Bash'`            | `['Read','Write','Bash']`                     |
| skill `name` equal to slug                          | key gone, no note                             |
| `description` with a newline and double spaces      | one line, single spaces                       |

Confirm `tools: []` and missing `applyTo` semantics against `COPILOT_AGENTS_DOC` and `COPILOT_INSTRUCTIONS_DOC` while
reviewing this step. The behaviour above is safe either way, but the wording may need adjusting.

### 5. Copilot body normaliser `[worker:high]`

Files: new `src/authoring/import/copilot-body.ts`, new `test/authoring/import-copilot-body.test.ts`.

`normalizeCopilotBody(kind, rawBody)` returns `{ body, title?, whenToUse?, argumentHint?, args?, notes }`. Each `Generated`
line and heading below is what the emitters write; quote them from the specs rather than retyping loosely.

- `rule`, `agent`: a first non-blank line `# X` sets `title: 'X'` and is removed. For `rule`, a following line matching
  `^<!-- Generated by sigil\b.*-->$` is also removed.
- `skill`: after an optional leading `## Boundary` block (kept in place), a `## When to Use` section sets `whenToUse` and is
  removed, ending before the next `**Arguments:** ` line or next heading. A `**Arguments:** X` line right after that point
  sets `argumentHint: 'X'` and is removed. The same section found later in the body stays where it is.
- `prompt`: apply `fromCopilotPlaceholders`, setting `args` when non-empty.
- All kinds: `reverseLexicon` with the Copilot target's lexicon runs on `body` and on `whenToUse`. Read it through
  `getTarget('copilot').lexicon`: `test/targets/provider-registry.test.ts` forbids importing a provider folder from
  outside `src/targets/`, so `authoring/` can't import `COPILOT_LEXICON`.
- A remaining `## Boundary` heading adds the note
  `body keeps the generated ## Boundary section; set relatedArtifacts in the catalog file`. A remaining
  `## Coding guidelines to apply` heading adds the note
  `body keeps the generated ## Coding guidelines to apply section; wire uses.rules with sigil patch`.

| Case                                                               | Expected                                         |
| ------------------------------------------------------------------ | ------------------------------------------------ |
| rule with `# Async (TypeScript)`, generated comment, `## Rule one` | `title` set; body starts `## Rule one`           |
| hand-written rule `# Style` then text, no comment                  | `title: 'Style'`, text kept                      |
| rule with a comment that isn't sigil's                             | comment kept                                     |
| rule with no H1                                                    | no `title`, body unchanged                       |
| agent `# Reviewer`, `## Boundary` block, `You are…`                | `title` set, Boundary kept, the Boundary note    |
| skill with `## When to Use`, `**Arguments:** [x]`, `# Document`    | both fields set; body starts `# Document`        |
| skill with only `**Arguments:** [x]` first                         | `argumentHint` set, no `whenToUse`               |
| skill with `## Boundary`, then `## When to Use`                    | field set, Boundary kept, the note               |
| skill with `## When to Use` after other content                    | no field, section unchanged                      |
| skill with multi-paragraph When to Use                             | both paragraphs in `whenToUse`                   |
| skill body containing `# Heading` first                            | H1 kept (skills get no emitted H1), no `title`   |
| prompt `${input:audience}`                                         | body `{{audience}}`, `args: [{name:'audience'}]` |
| skill body with `the request you were given`                       | `{sigil:arguments}`                              |
| body with the Coding guidelines heading                            | section kept, the note                           |
